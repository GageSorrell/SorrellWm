# Docusaurus Websites

Generated documentation sites use Docusaurus 3.10.x with the classic preset, React-powered MDX, Shiki 4, and `@shikijs/twoslash`. The landing page is served at `/`; documentation is served below `/docs`.

## Shared Configuration

`docusaurus.config.mjs` is deliberately small:

```js
import { DefineDocusaurusConfig } from "@sorrell/site-core/Docusaurus";
import Definition from "./website.config.json" with { type: "json" };

export default DefineDocusaurusConfig(Definition);
```

The factory supplies:

- the site URL `https://<Subdomain>.sorrell.sh` and `/` base URL;
- the classic preset with its blog disabled;
- documentation at `/docs` with `sidebars.ts`;
- `onBrokenLinks: "throw"`;
- the configured default locale and locales;
- light mode with system color-scheme detection;
- a navbar Docs link, version dropdown, and locale dropdown;
- the selected Docusaurus theme plugin; and
- Shiki/Twoslash as a documentation Rehype plugin.

The generated `sidebars.ts` creates an autogenerated sidebar from the entire `docs/` directory.

## Scripts

Run these inside the site or through npm's workspace option:

| Script | Purpose |
| --- | --- |
| `npm start` | Start the `en-US` development server. |
| `npm run start:es-US` | Start the `es-US` development server. |
| `npm run build` | Build every configured locale into `build/`. |
| `npm run write-translations` | Generate the `es-US` theme/plugin translation catalogs. |
| `npm run docs:version -- <version>` | Snapshot the current documentation as a named version. |
| `npm run typecheck` | Check generated TypeScript and TSX without emitting. |
| `npm run publish` | Publish the workspace with `sorrell-site publish .`. |

From the repository root, include the site package name:

```powershell
npm run start:es-US -w @sorrell/window-api-docs
npm run docs:version -w @sorrell/window-api-docs -- 1.0.0
npm run build -w @sorrell/window-api-docs
```

## Documentation and Routes

The initial English document is `docs/intro.mdx` and uses `slug: /`, so it appears at `/docs`. Add normal `.md` or `.mdx` files beneath `docs/`; the autogenerated sidebar discovers them.

The Spanish current-document tree begins at:

```text
i18n/es-US/docusaurus-plugin-content-docs/current/
```

The initial Spanish introduction mirrors the English slug. When adding or renaming English pages, update the localized content tree and generated translations before shipping.

Docusaurus emits the default locale without a locale prefix and nondefault locales beneath their locale name. Representative routes are:

```text
/                         default-locale landing page
/docs                     current default-locale documentation
/docs/<page>              current default-locale page
/docs/<version>/...       versioned default-locale documentation
/es-US/                   Spanish landing page
/es-US/docs               current Spanish documentation
```

Exact version route labels follow Docusaurus's generated version metadata.

## Versioning

Create a version only after the current documentation is ready to freeze:

```powershell
npm run docs:version -w @sorrell/window-api-docs -- 1.2.0
```

Docusaurus writes versioned document and sidebar data into the website workspace. Commit those files. Continue editing `docs/` for the next/current version; edit the generated version directory only to correct an already released version intentionally.

Run the all-locale build after creating a version. The version and locale dropdowns are always present in the standard configuration, so broken version metadata or missing localized pages should be caught before publication.

## React in MDX

MDX can import and render React components normally:

```mdx
import { InstallCommandPanel } from "@sorrell/ui";

<InstallCommandPanel packageName="@sorrell/windows" />
```

The generated `src/theme/MDXComponents.tsx` also registers shared components globally:

```tsx
import MDXComponents from "@theme-original/MDXComponents";
import { InstallCommandPanel } from "@sorrell/ui";

export default {
    ...MDXComponents,
    InstallCommandPanel
};
```

After registration, MDX can use `<InstallCommandPanel packageName="@sorrell/windows" />` without a local import. Extend this module to define the shared MDX vocabulary for a particular site, while retaining the original component map.

## Shiki and Twoslash

All code blocks pass through Shiki with `github-light` and `github-dark` themes. Twoslash is opt-in: only a fence carrying the `twoslash` meta marker runs the Twoslash transformer.

````mdx
```ts twoslash
interface WindowReference {
    readonly title: string;
}

const windowReference: WindowReference = { title: "Editor" };
windowReference.title;
```
````

An ordinary fence remains on the normal Shiki path:

````mdx
```ts
const title = "Editor";
```
````

Twoslash evaluates the sample with TypeScript, so examples must type-check and their imported packages must be available to the website workspace. The rich renderer adds hoverable type information to the generated markup.

## Landing Page

`src/pages/index.tsx` renders `DocsLanding` inside Docusaurus's `@theme/Layout`. It imports `@sorrell/ui/style.css` and receives initial content copied from the manifest.

Edit that page to add product-specific sections, icons, or behavior. Use `customSections` to insert arbitrary React content between the feature grid and final call to action. See [Landing pages and themes](./LandingAndThemes.md).

## Customizing Configuration

For standard sites, keep `DefineDocusaurusConfig`. If a site needs additional Docusaurus options, spread or amend the factory result in `docusaurus.config.mjs`:

```js
import { DefineDocusaurusConfig } from "@sorrell/site-core/Docusaurus";
import Definition from "./website.config.json" with { type: "json" };

const config = DefineDocusaurusConfig(Definition);

export default {
    ...config,
    customFields: {
        productFamily: "Windows"
    }
};
```

Preserve `/docs`, localization, output, and theme conventions unless the site intentionally opts out of the shared platform.
